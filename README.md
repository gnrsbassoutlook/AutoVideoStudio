# 智绘声影 2.0 + 剪映自动视频工作台 (AutoVideoStudio)

> 🎙️ 专为 AI 视频制作（ComfyUI / 剪映）量身打造的全自动时间轴对齐、提示词时长注入、批量运镜与音频管理工具箱。

---

## 🍎 Mac 用户第一次请先双击 `init.command`

`git clone` / 下载到本地后，**先双击运行一次 `init.command`**，再双击 `start-avs_mac.command` 等任何脚本。

**为什么要多这一步**：macOS 会给从网络来的文件打**隔离属性**（`com.apple.quarantine`），而 zip 解压、网盘下载、跨盘拷贝还会顺手把脚本的**可执行位**（`chmod +x`）弄丢。两种情况症状不同：

| 症状 | 原因 |
| --- | --- |
| 双击报「无法打开，因为来自身份不明的开发者」 | 隔离属性没清（Gatekeeper 拦截） |
| 双击**完全没反应**，毫无提示 | 可执行位丢了 |

`init.command` 一次性把这两件事做完，省得逐个 `chmod` / `xattr` 敲一遍：

- 给目录下所有 `*.command` / `*.sh` 补回可执行权限
- 清掉 `com.apple.quarantine`（这就是触发弹窗的元凶）
- 顺带体检：哪个脚本被转成了 Windows 的 CRLF 换行会一并提醒（CRLF 会报 `bad interpreter ... ^M`）

终端里跑也一样：

```bash
cd /path/to/AutoVideoStudio
chmod +x init.command     # 万一它自己也没权限
./init.command
```

> Windows 不需要这一步 —— 隔离属性和 Unix 可执行位都是 macOS 独有的东西。

## ✨ 核心特性

### 1. ✂️ 文本与提示词处理中心

- **SRT 时间轴注入 ComfyUI 提示词时长**：根据字幕空隙精准计算帧数（如 `560f`）或秒数（如 `22.4s`），支持设置安全冗余系数（如 1.02x），杜绝 AI 视频生成算力浪费。
- **字幕字符级映射对齐**：通过标准校对 TXT 文本反向重塑语音识别出的 SRT 字幕时间轴。
- **文本符号清洗**：专为 TTS 配音设计，剔除多余标点符号，保持语音连贯。
- **分镜提示词自动提取**：自动格式化序号、双语标题提取与绘图 Prompt 清洗。

### 2. 🎬 剪映工程自动化处理

- **图文/视频智能吸附字幕**：自动填满空隙，末尾精准吸附全局音频终点，杜绝片尾黑屏。支持智能降速 + 复制拼接。
- **动静分离运镜**：自动跳过视频素材，仅为图片批量添加推拉摇移关键帧与高斯模糊防黑边背景。
- **视频自带杂音管理**：支持一键将素材视频自带的声音剥离到独立音轨或批量物理静音。
- **音频名生成标题卡片**：自动读取音频片段文件名并在独立文本轨道生成居中排版的标题卡片。

## 🛠️ 安装与运行

### 1. 克隆本项目

```bash
git clone https://github.com/gnrsbassoutlook/AutoVideoStudio.git
cd AutoVideoStudio
```

### 2. 【Mac 必做】跑一次 `init.command`

双击 `init.command`，给所有 `.command` 脚本补回可执行权限并解除隔离属性，原因见上一节。

终端等价写法：

```bash
chmod +x *.command
xattr -dr com.apple.quarantine .
```

> Windows 跳过这一步。

### 3. 安装依赖

```bash
pip install -r requirements.txt
```

### 4. 启动

| 平台 | 双击这个 |
| --- | --- |
| Mac | `start-avs_mac.command` |
| Windows | `start-avs_win.bat` |

终端等价：

```bash
python3 AutoVideoStudio.py
```

> 之前文档里写的 `python3 app.py` 是笔误，主程序文件是 `AutoVideoStudio.py`。

## 🔄 同步脚本（push / update）

两个平台各有一套，双击即可运行，不需要敲命令。

| 平台 | 推送到 GitHub | 从 GitHub 拉取 |
| --- | --- | --- |
| Windows | `push_avs.bat` | `update_avs.bat` |
| Mac / Linux | `push_avs.command` | `update_avs.command` |

### push（推送本地改动）
1. 自动检测远程通道：**SSH 可用就用 SSH，不可用自动回退 HTTPS**，不用手动改配置
2. 推送前先 `fetch` 比对，本地落后时自动 `pull --rebase --autostash`，从根上减少冲突
3. 列出当前改动让你确认，没有改动就直接退出，不会制造空提交
4. 让你输入 Commit 说明，直接回车则用 `Auto update: 时间戳`

### update（拉取远程代码）
1. 拉取远程最新状态，列出最近 **20 条提交**（序号 1 = 最新）
2. 标出你本地当前停在第几条
3. **输入 1-20 的序号选择要同步到哪一条**，回车默认选最新的 1，输入 `Q` 取消
4. 选的历史前方提交 → 安全快进；选了旧版本或分叉 → 明确警告并要求输入 `YES` 才执行
5. 本地有未提交改动时自动 `stash`（可用 `git stash pop` 取回），不会弄丢你的东西
6. 同步完列出本次变动的文件，并询问是否更新依赖

> **首次使用请先双击一次 `init.command`**（见文章开头）：它等价于 `chmod +x *.command` + 清 `com.apple.quarantine`，Windows 不需要。
> 若提示 `bad interpreter ... ^M`，说明文件被转成了 CRLF，执行 `sed -i '' 's/\r$//' *.command`。

## 🔒 附：JianyingPro59Guard.exe — 剪映专业版 5.9 版本锁定守护

### 为什么仓库里会有一个 .exe

因为这个项目的自动化，**严重依赖剪映专业版 5.9 的草稿结构和行为**——草稿目录、版本目录、素材与轨道排布、缩略图缓存位置，都是对着 5.9 写的。

但 PC 上的剪映并不老实：

- **自己偷偷升级**：后台静默拉新版，某天打开发现界面和草稿结构都变了；
- **被第三方管家代升级**：像 360 软件助手这类工具会"顺手"帮你把软件更到最新。

一旦被升上去，这边的自动化链路就可能整条失效，而排查起来极其费时间。**与其每次出事再救火，不如从源头把版本钉死。**

于是有了这个纯 Windows 的守护小工具：让剪映**停在 5.9 不动**，谁来升都不好使。
🍎 **Mac 用户请直接忽略这个文件**，它跟 macOS 无关，也永远不会被执行；它的存在只是为了让 Windows 机器 clone 下来后开箱即用。

### 它是干嘛的

一个独立的小工具，用来**把剪映专业版钉死在 5.9，禁止任何形式的升/降级**——
无论是剪映自己的自动更新，还是 360 软件助手之类的第三方管家偷偷帮你"升级"。

关键在于它**只锁软件本体，不锁功能**：

- ✅ 字幕识别、素材下载、在线素材库等**联网功能照常**
- ✅ 草稿工程、下载素材、预设、缓存（`User Data` 目录）**照常读写**
- ❌ 软件本体（`Apps` 目录）**任何人、任何程序都改不动**

简单说就是："用随便用，动不许动。"

### 怎么用

`JianyingPro59Guard.exe` 是 PyInstaller 打包的单文件程序，**不需要装 Python，拷到任何 Windows 电脑双击就能跑**。

> ⚠️ 必须**右键 → 以管理员身份运行**，否则权限不足，装不上防护。

首次使用按这个顺序：

```

[1] 安装守护       → 提示选模式时输入 S（严格模式）
[8] 创建完整备份   → 约 1.3G，被破坏后唯一能完整回滚的手段，建议做
[2] 立即体检       → 确认显示"正常"就装好了

```

装完之后它会注册一个**每 15 分钟执行一次的计划任务**在后台值守，你不用管它。
想卸载就运行 `[10] 完全卸载守护`。

以后你**自己**想升级剪映了：`[5] 临时解锁` → 正常升级 → `[7] 重建基线` + `[8] 重做备份` + `[6] 恢复锁定`。

### 四层防护

| 层 | 机制 | 挡住什么 |
| --- | --- | --- |
| 1 | **本体只读锁** — `Apps` 目录对 Everyone 设置拒绝写入/删除/新建 | 360 软件助手、任何第三方改写程序文件（SYSTEM 权限也一样被挡） |
| 2 | **定向断更新程序的网** — 防火墙出站规则只按完整路径拦 `5.9.0.xxxxx\update.exe` | 剪映自更新程序联网下载新版本；主程序联网不受任何影响 |
| 3 | **版本指针 + SHA256 基线** — 校验 `Configure.ini` 的 `last_version`，并对 2000+ 个本体文件做 SHA256 指纹 | 新增版本目录、篡改版本指针、替换 DLL（包括伪造成相同大小的"同大小掉包"） |
| 4 | **每 15 分钟值守** — 计划任务自动巡检 | 新版本目录搬进隔离区、版本指针从基线副本还原、受损文件从完整备份回滚、干掉从非基线目录启动的进程 |

### 关于 `update.exe`

剪映版本目录里的 `update.exe` 是自带的升级器。**不建议直接删**——
主模块 `VECreator.dll` 里有硬编码调用它的代码路径，删了可能导致那一路报错。

工具提供 `[12] 阉割 / 还原`：保留文件名、内容置 0 字节。
这样调用者找得到文件不会报错，执行起来什么都不会发生，而且随时能还原。
默认是**不处理**的，需要你自己选择。
